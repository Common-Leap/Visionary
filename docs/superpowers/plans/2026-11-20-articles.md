# Articles in Movesets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every article a linked moveset makes is found, attributed to its owner and source, shown with its settings and where each comes from, editable and saved back exactly, sent live, and flown in the preview from those settings.

**Architecture:** A new pure module tree `src/articles/` reads clones, article IDs, status settings and param blocks from the moveset source and data. A typed `ArticleCall` replaces the raw handling of `ArticleModule::` lines, so the timeline, move nodes and preview walk all read one model. The writers reuse `acmd_src`'s byte-exact rewrite path. Phase B extends the plugin's capture and injection to the selected fighter's articles. Phase C feeds the resolved settings into upstream's `article_preview`.

**Tech Stack:** Rust 1.97.1, egui 0.37, syn 3 (already a dependency), prc-rs 1.6, smashline 2 source conventions. Single binary crate `visionary`: tests are `#[cfg(test)]` modules, run with `cargo test --bin visionary <filter>`.

**Spec:** `docs/superpowers/specs/2026-11-20-articles-design.md`

## Global Constraints

- Work on branch `merge-upstream-0.3` in the `Visionary-merge` worktree. Never push. Commits carry no `Co-Authored-By` line.
- Saving must not change any byte of a moveset's source the user did not edit. CRLF files stay CRLF.
- A value is never shown without its origin. A `Computed` value is never overwritten with a literal.
- A clone's params come from the new owner's `param_<new_name>`. They are never borrowed from the source article.
- Plugin hooks act only on the selected fighter's own articles. Existing fighter-capture guards stay unchanged.
- UI copy is in plain words (upstream's style): "Creates the fireball", not `generate_article`.
- Anything that can't be modelled is kept verbatim and explained in a sentence. It is never dropped.
- Clone compatibility data credits the sheet's verifiers and links its source.
- **ssbu-modding-genius is the authority for SSBU facts.** Every constant, `Module::fn` signature, hash and kinetic op a task's code or tests name is checked with `lookup` (vanilla, tier 0) or `search_docs` (crate, locked revision) before it is written. Every SSBU Rust fixture is passed through `validate_code`. Plugin changes (Task 11) get a `ssbu-modding-genius:code-validator` pass before commit. Corpus shapes come from `search_corpus` / `find_usages` and are cited `repo · path:line (tier N, era)` in the test's doc comment.
- Verified signatures (lookup, 2026-11-20): `ArticleModule::shoot(acc, i32, ArticleOperationTarget, bool)`, `ArticleModule::remove_exist(acc, i32, ArticleOperationTarget)`, `PostureModule::set_scale(acc, f32, bool)`, `ARTICLE_OPE_TARGET_ALL = 0, FIRST = 1, LAST = 2, TERM = 3, NONE = 0xFFFFFFFF`, `WEAPON_INSTANCE_WORK_ID_INT_LIFE = 0x10000005`.

## Review Focus

1. **Duplicate article registrations.** A moveset registers the same article agent's script in two files. Expect: shown as a conflict (as `SourceIndex::conflict` does for fighter scripts), never one picked silently. Test in Task 3.
2. **Uninitialised clone IDs.** A clone ID static (`FIGHTER_X_GENERATE_ARTICLE_Y += clone_weapon(…)`) is 0 until install runs. Expect: spawns resolve by the symbol's name, never by a numeric value. Test in Task 3.
3. **`ARTICLE_OPE_TARGET_ALL` with several live copies.** Expect: the preview removes or hides every copy of that article, not just the last one. Test in Task 12.
4. **Params shipped as `vl.prcxml`** (Shy Guy). Expect: an edit writes the prcxml and never creates a binary `vl.prc` beside it. Test in Task 6.
5. **CRLF source files** (most of the corpus on Windows). Expect: every writer keeps CRLF. Test in Task 8.

### Task 2: Read `clone_weapon` registrations

**Files:**
- Create: `src/articles/clones.rs`

**Interfaces:**
- Consumes: `crate::project_consts::ProjectConsts::{scan, get}`.
- Produces: `pub struct CloneDecl { pub new_owner: String, pub new_name: String, pub src_owner: Option<String>, pub src_kind: String /* "WEAPON_KIND_MARIO_FIREBALL", no '*' */, pub use_original_code: bool, pub id_bindings: Vec<String> /* names the generate id is stored in */, pub kind_bindings: Vec<String> /* names the weapon kind is stored in (new API) */, pub file: PathBuf, pub line: usize }`, `pub struct UnresolvedClone { pub file: PathBuf, pub line: usize, pub text: String, pub reason: String }`, and `pub fn read_clones(sources: &[(PathBuf, String)], consts: &ProjectConsts, fighter_dirs: &[String]) -> (Vec<CloneDecl>, Vec<UnresolvedClone>)`.

The rules:
- **Telling the signatures apart.** Five arguments is the old API: `(src_owner, src_kind, new_owner, new_name, bool)`. Four arguments is the new API: `(new_owner, new_name, src_kind, bool)`.
- **Old API IDs.** The ID binding is the left-hand side of `X += clone_weapon(…)` or of `X = N + clone_weapon(…)`.
- **New API IDs.** Follow `let v = clone_weapon(…)` to `A.get_or_init(|| v.generate_id)` (goes in `id_bindings`) and `B.get_or_init(|| v.weapon_id)` (goes in `kind_bindings`). Accept `.set(…)` and plain assignment the same way.
- **Source owner for the new API.** Take the longest fighter name in `fighter_dirs` such that `src_kind` starts with `WEAPON_KIND_<OWNER>_`.
- **Arguments that aren't literals.** A name argument that is a `const &str` resolves through a const scan of the same sources (`const REDSHELL_ORIGIN: &str = "…"`). A call inside `for (name, source) in [(…), …]` over a literal array is unrolled, one `CloneDecl` per element. Anything else goes to `UnresolvedClone` with a one-sentence reason.
